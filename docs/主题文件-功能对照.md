# 澎湃OS / MIUI 主题（.mtz）拆解报告 —— 哪个文件对应哪个界面功能

> 样本：`机甲爱丽丝澎湃OS3主题.mtz`（346 MB / 67 个顶层条目）
> 加载器：`base.apk` = **ThemeKit**（包名 `com.dreallab.themekit`，实为 `com.drealab.themekit`，版本 2.26.4）
> 结论先行：**.mtz 是一个「装着若干个小 zip 的 zip」**。每个小 zip 是一个"换肤模块"，
> 模块名 = 要替换的系统应用包名；模块里的 `res/drawable-*/xxx.png` 就是那个界面上的一张图。

---

## 一、两个文件到底是什么

| 文件 | 真实身份 | 判断依据 |
|---|---|---|
| `base.apk` | **ThemeKit 主题安装/管理 App**（不是系统自带主题商店） | `application-label='ThemeKit'`；`ThemeIntentInstallActivity` 注册了 `ACTION_VIEW` + `pathPattern=".*\.mtz"`；内部用 Shizuku（`rikka.shizuku`、`assets/shizuku.apk`）执行安装 |
| `机甲爱丽丝澎湃OS3主题.mtz` | 一套**澎湃OS 3.0 完整主题**（uiVersion 17 / miuiAdapterVersion 4.0） | `description.xml` 里 `<uiVersion>17</uiVersion>`；ThemeKit 打开后显示「主题适配：HyperOS3」「框架版本：17」 |

ThemeKit 能接受的入口有三个（这是我们生成的包必须满足的契约）：

```
ACTION_VIEW   scheme=content|file   mimeType=*/*   pathPattern=".*\.mtz"
ACTION_VIEW   mimeType=application/zip | x-zip-compressed | x-msdownload | x-7z-compressed | octet-stream
ACTION_SEND   mimeType=*/* 或上面几种
```

```
│     preview_mms_0.jpg             1440×3200 短信预览
│     preview_aod_0.jpg             1080×2160 息屏预览

├── wallpaper/                    ← 壁纸（目录，不是 zip）
│     default_wallpaper.jpg         2160×4800 桌面壁纸（注意：实际是 PNG 数据改了 .jpg 后缀）
│     default_lock_wallpaper.jpg    2160×4800 锁屏壁纸
├── icons                         ← 【zip】图标包：res/drawable-xxhdpi/<应用包名>.png
├── lockscreen                    ← 【zip】锁屏样式：advance/manifest.xml + config.xml + 素材
├── aod                           ← 【zip】息屏显示：aod_description.xml + content/img/*.png
├── framework-res                 ← 【zip】系统框架资源：全局对话框/按钮/开关/输入框
├── com.android.systemui          ← 【zip】状态栏 + 通知栏下拉 + 控制中心 + 虚拟导航键
├── miui.systemui.plugin          ← 【zip】控制中心「新样式」插件（磁贴卡片、音量条、媒体卡片）
├── com.miui.home                 ← 【zip】桌面（启动器）：搜索框、翻页点、文件夹、长按菜单
├── com.android.settings          ← 【zip】设置
├── com.android.contacts          ← 【zip】联系人 / 拨号
├── com.android.mms               ← 【zip】短信
├── com.android.deskclock         ← 【zip】时钟
├── com.android.calendar / camera / phone / fileexplorer / thememanager / updater …
└── （其余每个系统/第三方 App 一个同名 zip）
```

**关键规律：顶层条目名 = 目标 App 的包名。** 手机里叫 `com.android.mms`，主题里就叫 `com.android.mms`。
`wallpaper/`、`preview/`、`icons`、`lockscreen`、`aod`、`framework-res` 是几个固定专用名。

## 三、模块（内层小 zip）的内部结构

以 `com.android.systemui` 为例：

```
com.android.systemui                 ← 【内层 zip】
├── theme_values.xml                 ← 颜色/尺寸/布尔值覆盖（浅色）
├── theme_fallback.xml               ← 「资源名 → 实际文件名」的映射表 + 中文注释（最有用的说明书）
├── res/
│     drawable-xxhdpi/*.png          ← 2x 密度图片（绝大多数图在这里）
│     drawable-nxhdpi/*.png          ← 「超大」密度图片
│     raw-xxhdpi/stat_sys_battery*.png ← 电池图标（原始资源）
├── nightmode/                       ← 深色模式（全部同名同结构）
│     res/drawable-xxhdpi/…
│     theme_values.xml / theme_fallback.xml
└── framework-miui-res/res/…         ← 覆盖 MIUI 框架资源（较少用）
```

三条实用结论：

1. **要改哪张图，就把同名同路径的文件塞进对应模块即可**，不需要 `theme_values.xml`。
   证据：`com.eg.android.AlipayGphone` 模块里**只有** `res/drawable-xhdpi-v4/start_logo.png` 两张图，没有别的文件，却是正式发布主题。
2. **`nightmode/` 目录 = 深色模式**。只在 `res/` 放图 → 只改浅色；两边都放 → 深浅色都改。
3. **`.9.png` 是九宫格**（可拉伸背景）。文件名必须以 `.9.png` 结尾，且图片四周要有 1px 的黑色拉伸标记，
   否则系统按普通图处理会变形或直接不生效。

## 五、给"主题制作工具"的落地映射

工具把上面所有可用图片整理成 **11 个界面分类 / 93 个分组 / 5088 个槽位**，
每个槽位 = 「一张要替换的图」+「它对应的功能说明」+「目标尺寸」+「是否九宫格」。

| App 里的界面卡片 | 对应 MTZ 内容 | 关键槽位示例 |
|---|---|---|
| 桌面壁纸 / 锁屏壁纸 | `wallpaper/default_(lock_)wallpaper.jpg` | 2 个，各 1440×3200 |
| 状态栏 | `com.android.systemui` 的 `stat_sys_*` / `status_bar_toggle_*` / `ic_sysbar_*` | 电池、信号、WiFi、导航键 |
| 下拉通知栏 | `com.android.systemui` 的 `notification_*` / `ic_qs_bg_*` / `panel_round_corner_bg.9.png` | 通知面板背景、通知条目、清除按钮 |
| 控制中心 | `ic_cc_qs_*` / `qs_control_*` + `miui.systemui.plugin` | 开关激活/未激活、大磁贴、亮度条 |
| 桌面启动器 | `com.miui.home` | 搜索框、翻页指示点、文件夹、长按菜单 |
| 应用图标包 | `icons/res/drawable-xxhdpi/<包名>.png`（401 个） | 支持整包 zip 导入 |
| 息屏显示 AOD | `aod/content/img/img_nuom_*.png`（91 帧） | 自动附带 `aod_description.xml` |
| 锁屏样式 | `lockscreen/advance/*` | 建议配合「基础模板」 |
| 全局系统控件 | `framework-res` | 对话框、按钮、开关、滚动条 |
| 系统应用换肤 | 40 个应用模块（设置/联系人/短信/时钟/日历/相机/安全中心…） | 每个 App 的窗口背景、对话框、列表项 |
| 主题预览图 | `preview/preview_*_0.jpg` | 换壁纸时自动生成 |

**每个槽位的处理规则**

| 情况 | 处理 |
|---|---|
| 目标以 `.9.png` 结尾 | 按目标尺寸裁剪 → 四周补 1px 透明边 → 在上边/左边 30%~70% 处画黑色拉伸标记（生成合法九宫格） |
| 目标是 200×200 以上的大图（壁纸、窗口背景） | 等比缩放 + 居中裁切（cover）铺满目标尺寸 |
| 目标是小图标（电池、信号、图标包） | 等比缩放完整放入目标尺寸，居中，保留透明（fit） |
| 目标是 `.webp` | 按 WebP 编码（API 30+ 用无损） |
| 目标是 `.jpg` | 按 JPEG 质量 93 编码，有透明通道则压到黑底 |

**打包规则**

* 未选择「基础模板」→ 只把用户填过的槽位打成**局部主题**（`description.xml` + 用到的模块），
  系统主题管理器/ThemeKit 都接受这种只含部分模块的包（正如样例里的支付宝模块只有 2 张图）。
* 选择了「基础模板 .mtz」→ 逐条目重写：模板里**没用到的模块原样复制**，用到的模块把内层 zip 解开、
  替换对应文件后重新压回去。这样锁屏样式、息屏、图标、各应用皮肤都能保留。

## 七、已知限制

1. **锁屏样式**：`lockscreen/advance/manifest.xml` 是布局脚本，无法由一张图推导。不导入基础模板时，
   锁屏只能改背景图（`default_lock_wallpaper.jpg`），锁屏模块本身需要模板。
2. **字体 / 铃声 / 开机动画 / 动态壁纸**：样本主题里没有，本工具暂未覆盖。
3. **深色模式**：默认只写浅色（`res/`）。深色变体在槽位列表里以「深色」分组单独出现，可单独上传。
4. **主题适配机型**：`uiVersion=17`（澎湃OS 3.0）。MIUI 14 / HyperOS 1-2 的机型需要相应改小该值。
5. ThemeKit 显示「大小：不可用」是它自身对 `content://` URI 的限制，不影响导入。
